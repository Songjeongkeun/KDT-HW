# 한국어 문서 질의응답 미니 프로젝트

## 한 줄 소개

KLUE-RoBERTa를 KorQuAD 1.0에 fine-tuning하여, 주어진 한국어 문단과 질문에서 답변 구절을 찾아 원문에 표시한다.

## 범위와 결과물

- 입력: 한국어 문단 1개와 질문 1개
- 출력: 문단 안의 연속된 답변 구절 및 근거 위치
- 첫 결과물: [한국어_문서_질의응답_KorQuAD.ipynb](한국어_문서_질의응답_KorQuAD.ipynb)
- 실행 환경: [환경_설정.md](환경_설정.md) — 프로젝트 `.venv`, CUDA PyTorch, JupyterLab 실행 방법
- 과제 3 제출용 초안: [과제3_한국어_문서_질의응답_보고서.md](과제3_한국어_문서_질의응답_보고서.md) — 여섯 요구사항을 순서대로 정리하고 실제 실행 결과를 기록하는 문서
- 과제 2 모델 조사: [과제2_KLUE-RoBERTa_모델조사.md](과제2_KLUE-RoBERTa_모델조사.md)
- Python 실행 파일: [한국어_문서_질의응답_KorQuAD.py](한국어_문서_질의응답_KorQuAD.py) — 학습·평가·새 입력 예측 명령 제공
- 데이터: KorQuAD 1.0 학습 60,407개, 공개 검증 5,774개
- 모델: Hugging Face `klue/roberta-base` + 추출형 질의응답 헤드

## 과제 3 요구사항 대응

| 요구사항 | 프로젝트에서 보여줄 내용 |
| --- | --- |
| 모델과 데이터셋 소개 | KLUE-RoBERTa 구조, KorQuAD의 질문·문단·답변 위치 |
| Tokenizer 전처리 | 질문·문단 쌍 토큰화, 긴 문단 슬라이딩 윈도, 문자 위치→토큰 위치 |
| Fine-tuning | 답변 시작·끝 토큰 예측, 내부 검증 loss로 최적 epoch 선택 |
| 학습 및 평가 | loss 곡선, 공개 검증의 정규화 EM·글자 F1, 오류 사례 |
| 새 문장 예측 | 직접 작성한 문단·질문으로 답변 추출과 근거 강조 |
| 문제점 및 개선 | 긴 문서, 답이 없는 질문, 위키백과와 실제 문서의 차이 |

## 실행 순서

1. GPU 사용 가능한 Jupyter/Colab에서 노트북을 연다.
2. 설치 셀을 실행하고 필요하면 커널을 재시작한다.
3. `FAST_DEV_RUN=True`로 전체 셀을 순서대로 실행해 흐름을 확인한다.
4. `FAST_DEV_RUN=False`로 바꾸고 처음부터 실행해 전체 데이터를 학습한다.
5. 검증 지표·오류 사례·새 입력 예측 화면을 기록한다.
6. 같은 과정을 Python 실행 파일에서 반복하고 생성된 `metrics.json`, `training_history.csv`, `error_examples.csv`를 확인한다.

## 실험 설계

학습 자료에서 기사 제목 단위로 내부 학습/검증을 분리한다. 내부 검증은 최적 epoch를 선택하는 데 사용한다. 공개 KorQuAD 검증 세트는 최종 평가에 사용한다. 공개 테스트 정답은 제공되지 않는다. 노트북의 정규화 EM·글자 F1은 자체 구현 지표이며 공식 리더보드 점수로 표기하지 않는다.

## 실무적 확장

이 모델은 **제공된 문단에서 답변 구절을 추출**한다. 긴 문서 전체를 다루려면 문단 검색을 앞단에 추가해야 한다. KorQuAD 1.0에는 답이 없는 질문에 대한 학습 사례가 없으므로, 답변 거절 기능은 별도 데이터와 평가가 필요하다.
